# Оптимизация алгоритмов ИИ — 18 ноября 2026

По просьбе автора сократить синхронные задержки ИИ без ослабления решений
оптимизированы только клиентские `core/ai_player.gd` и `core/match_state.gd`.
База сравнения — сохранённая перед работой текущая dirty-копия, а не Git HEAD:
`build/isolated/ai-algorithm-baseline-2026-11-18/manifest.json`.

## Изменения

- `choose_setup`: один приватный снимок на сочетание ворот и слота вместо
  нового снимка для каждого готового существа; порядок всех вариантов и RNG прежний.
  На строго каноническом пустом поле из шести слотов, когда все существа вне поля,
  одинаковый прогноз gate×uid используется для остальных позиций. У одной карты
  нет соседей/целей переноса и поддержки; номер слота не меняет угрозу.
  Любое непустое/неканоническое поле сохраняет отдельный прогноз каждой позиции.
- Прогноз угрозы размещения: один публичный каталог/исключённые использованные ID
  и список совместимых гипотез ворот на решение; фильтр проверяет только
  Сдвиг/Подмену, как и прежняя модель риска. Вероятности используют полные группы.
- Повторно используются исходный закрытый `BattleResult` и приватные снимки
  последовательных гипотез ворот. `PowerCalc` по-прежнему выполняет каждый
  содержательный расчёт, включая открытие ворот, цели, Подмену и Сдвиг.
- Прогноз ответа: публичный каталог, размер скрытой руки и веса групп живут
  в одном решении. Результат прежнего DP запоминается по числу подходящих ID
  каждого класса; исходный DP зависит именно от этих чисел, размеров групп,
  известных ID и размера руки. Числа сочетаний для класса вычисляются один раз,
  порядок операций DP сохраняется. Выбор конкретных карт и расчёты боя не кэшируются.
- `duplicate_full()` сразу строит полную независимую копию; больше не создаёт
  маскированные копии игроков/слотов перед повторным полным клонированием.
  Маскирование `duplicate_view(player)` и `duplicate_view(-1)` сохраняется.
- Исторический стенд `tools/ai_forecast_timing.gd` сохраняет свой прежний
  override прогноза через новый внутренний helper; он не используется как
  dirty baseline этого сравнения.

Сила, эвристики, глубина и порядок поиска, набор пар ответов, вероятности,
стоимость карт, tie-break и количество/порядок RNG не менялись. Кэши локальны
одному решению; они не переживают добор, новый вид, ход или матч.

## Результат измерений

Независимый Sol high сравнил на одном Linux-хосте две изолированные мини-сборки
`core/` + `data/` с теми же колодами/состояниями. Godot 4.7.2
`ed1daf0bf`; headless, 60 FPS, без графики и физического полёта. Последовательно
**AB BA BA AB**, по четыре процесса на версию; каждый сначала прогревается
одним полным seed777, его время отбрасывается. В таймере — тело публичного
метода обычного `AIPlayer`, без сериализации/metadata и AuditAI-перехвата.
Это синхронная wall latency, включая планировщик, не exclusive CPU time.

Семь HARD матчей × четыре повторения на версию; NORMAL/EASY входят в
эквивалентность, но не в таблицу HARD. Времена — миллисекунды:

| Решение | n на версию | Медиана до → после | p95 до → после | Максимум до → после |
|---|---:|---:|---:|---:|
| Расстановка ворот | 240 | 43.046 → 25.2545 | 80.562 → 47.255 | 140.352 → 57.984 |
| Способность | 396 | 5.690 → 5.132 | 19.428 → 15.723 | 28.015 → 23.640 |
| Бросок | 24 | 38.1615 → 27.1055 | 69.424 → 51.196 | 74.721 → 52.689 |

Медиана расстановки сокращена в **1.70 раза**, способности — в **1.11 раза**.
На первом пустом поле seed777 медиана четырёх решений **107.9485 → 11.8805 мс**
(9.09 раза), seed31 **134.7815 → 26.6335 мс** (5.06 раза).
Во всём seed777 setup median **32.548 → 20.0515 мс** (n32), ability
**14.6225 → 11.4595 мс** (n28). Это одинаковый повторяемый конечный корпус,
а не независимая выборка всех возможных матчей. p95 — элемент отсортированной
выборки с индексом `floor(0.95*(n-1))`.
[Числа и команды](bench/timing-summary.json) ·
[Все парные решения](bench/paired-samples.json.gz).

Исторические 230.598/44.865 мс другого CPU probe не используются как baseline
этих коэффициентов: другие условия и прогрев. Пики после оптимизации всё ещё
могут быть заметны: setup **57.984 мс**, ability **23.640 мс** в этом корпусе.
Уменьшение постоянного времени кадра/FPS этим не доказано.

## Проверки

- Полные трассы **9 достижимых логических матчей, 423 шага, 414 внешних решений,
  331 внутренний `_score`** совпали точно: choices, AI RNG до/после, remembered
  gates, порядок/значения scores, все состояния/предпросмотры и controller RNG.
  Покрыты обе системы правил, три пула карт, три сложности, все шесть стихий,
  ничьи, Зеркало, Сдвиг/прерывания, ответы после карты, метки и used-состояния.
  Исходный seed777 сохранил колоды/команды и финал 32 шага/14 ходов/knockout.
- **1200** прямых случаев скрытых вероятностей совпали, в том числе native
  `var_to_bytes` без округления; **3600** проверок
  холодного/повторного memo и иных наборов matching дали исходные числа.
- **170** проверок полных копий в матчах и **5** дополнительных синтетических
  снимков проверили содержание, раздельную идентичность и вложенные изменения
  players/slots/creatures/attached/marks/cooldown/battle_context. Отдельно
  проверены full, view(-1), view(player), в том числе состояние трёх игроков.
- Для второго прохода: **936** сравнений exposure (156 gate×uid случаев на шести
  позициях), **126** setup-решений с перестановкой legal/сложностями, **7** true
  и **49** false проверок canonical guard. Результаты baseline/final точны.
- Первый проход: семь узких `ai-swap-combo ai-forecast ai-gust-risk ai-target-flow
  ai ai-gates ai-outcomes` — все PASS. После дополнительного empty-board cache
  повторены затронутые `ai ai-gates` — PASS; заново выполнены полная paired
  эквивалентность и AB-последовательность. Полный профиль не запускался.
  Исторический `tools/ai_forecast_timing.gd` прошёл `--check-only`.

Failures пусты, все запуски завершились с 0, runtime errors/утечек в логах нет.
В матчах не выбрана настоящая карта прикрепления; лимиты прикреплений проверены
адресным `ai-swap-combo`, nested copy fixtures и отдельными setup случаями.
Конечный корпус и независимое ревью подтверждают сохранение проверенного
поведения; это не исчерпывающий перебор всего пространства состояний.

## Воспроизведение и снимки

Финальные production SHA-256:

- `core/ai_player.gd`: `499facbf387825e69a193d6c369385591508e4fc64aae5fc9a0889ba4d75ceae`.
- `core/match_state.gd`: `162e17782df8b131cdb0fa05b58e664cee7529bf10b43e7d030570c042f6b2d4`.

Исходный dirty `ai_player.gd`: `8150cf9a3534bbbf5fddb0d767582413643af9820abc8e1733f1b2cf0512e6ff`.
В durable `bench/` сохранены SHA всех 54 входов `core/` + `data/` и компактный
[patch final → baseline](bench/reference-reverse.patch) двух изменённых файлов.
Это позволяет восстановить исходную реализацию без игнорируемого `build/`
и без копии ресурсов всего клиента. Нужны исходники, совпадающие с
[candidate manifest](bench/candidate-sha256.json); при дальнейших изменениях
сначала восстановите эту ревизию проекта. Runner откажется использовать другой
SHA вместо измеренного финала. Patch применяется только в изолированной
reference-копии, затем проверяется каждый [исходный SHA](bench/reference-sha256.json).
Production-файлы не откатываются.

Из корня проекта:

```sh
python docs/audits/2026-11-18-ai-algorithms/bench/run_paired.py --prepare --correctness --timing
python tools/check.py --profile gameplay --checks ai-swap-combo ai-forecast ai-gust-risk ai-target-flow ai ai-gates ai-outcomes
```

Первой командой mini-runtime создаётся в `build/isolated/`, импортируются
только core/data; режим correctness отдельно запускает trace, direct odds/copy
и setup-guard пробы. Режим timing последователен; не запускайте другой Godot
параллельно с измерением. Команды отдельных исторических запусков — в summary.
[Подробное воспроизведение и проверка patch](bench/REPRO.md).
Логи и сжатые raw JSON сохранены рядом с [harness](bench/harness.gd).
Независимые Sol high взаимно проверили обе части реализации и отдельно
инвариантность canonical empty cache; основную проверку выполнил третий Sol high.

## Границы

Это проверка логики и синхронного времени решений Linux/Godot 4.7.2;
точное логическое приземление не является физическим матчем. FPS,
GPU/cloth, графический матч, Windows, слабый CPU, прослушивание и выпуск
этим изменением не проверяются. EXE/PCK/ZIP не пересобирались и не публиковались.
Сервер и пользовательские настройки не менялись; прежние dirty-изменения
сохранены. `.codex/` не изменялся.
